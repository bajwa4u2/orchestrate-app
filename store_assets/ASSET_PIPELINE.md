# Orchestrate Asset Pipeline

Active Flutter app: `orchestrate_app`.

## Canonical source (brand canon)

**`assets/branding/icons/orchestrate_app_icon_dark_1024.png`** — 1024 × 1024
PNG, RGBA, opaque, the circular workflow mark in the founder-approved
brand register. This is the source of truth for every store-submission
asset under `store_assets/`.

The previous SVG source (`store_assets/source/orchestrate-app-icon-master.svg`)
and the programmatic mark drawn by `tool/generate_store_assets.ps1` are
**wrong-brand**: they render a navy + light-blue stylisation that does
not match the brand canon. They were removed (SVG) or flagged stale
(powershell script — see warning below) during the 2026-06-01 store-
asset alignment.

## Re-generating store assets

```bash
# From the orchestrate_app/ root.
python - <<'PY'
from PIL import Image
src = Image.open('assets/branding/icons/orchestrate_app_icon_dark_1024.png').convert('RGBA')
src.save('store_assets/source/orchestrate-app-icon-master-1024.png', 'PNG', optimize=True)
src.save('store_assets/ios/app-store-icon-1024.png', 'PNG', optimize=True)
src.resize((512, 512), Image.Resampling.LANCZOS).save(
    'store_assets/android/play-icon-512.png', 'PNG', optimize=True)
src.resize((300, 300), Image.Resampling.LANCZOS).save(
    'store_assets/windows/store-tile-300.png', 'PNG', optimize=True)
bg = Image.new('RGBA', (1024, 500), (0, 0, 0, 255))
icon = src.resize((400, 400), Image.Resampling.LANCZOS)
bg.alpha_composite(icon, ((1024-400)//2, (500-400)//2))
bg.convert('RGB').save(
    'store_assets/android/feature-graphic-1024x500.png', 'PNG', optimize=True)
PY
```

The canonical PNG is 1024 × 1024; the 1024 store outputs are byte-for-byte
copies of the canonical. The 512 and 300 outputs are Lanczos downsamples
— never upsampled. The 1024 × 500 Play feature graphic is the canonical
icon contained at 400 × 400 on the icon's own near-black background, no
text and no added brand elements.

### Quality limitation (recorded honestly)

The canonical brand source is 1024 × 1024. Apple's iOS submission and
the Google Play console accept 1024 PNG, so the maximum size never
requires upsampling. The canonical render at 1024 is itself the
authoritative resolution of this mark at this moment; if a sharper
master is needed later, the brand canon should ship a higher-resolution
source rather than this script up-rezzing.

## Store-submission paths owned by this pipeline

- Master PNG: `store_assets/source/orchestrate-app-icon-master-1024.png`
- Google Play icon: `store_assets/android/play-icon-512.png`
- Google Play feature graphic: `store_assets/android/feature-graphic-1024x500.png`
- iOS App Store icon: `store_assets/ios/app-store-icon-1024.png`
- Windows Store tile: `store_assets/windows/store-tile-300.png`

## Out of scope here (separate platform-icon flow)

The following runtime app-launcher icons are *not* regenerated by this
script and remain on their existing platform-icon flow. When the brand
canon is finalised they should be regenerated separately from the
canonical PNG:

- Android launcher icons: `android/app/src/main/res/mipmap-*/ic_launcher.png`
- Android adaptive icon foreground / background under `res/drawable*/`
- iOS app icon set: `ios/Runner/Assets.xcassets/AppIcon.appiconset/*.png`
- Web favicon: `web/favicon.png`
- Web PWA icons: `web/icons/Icon-{192,512}.png`, `Icon-maskable-{192,512}.png`
- Windows app icon: `windows/runner/resources/app_icon.ico`

## Stale tooling notice

**`tool/generate_store_assets.ps1`** draws the icon programmatically
via GDI+ — the path it draws is the *old* navy+blue stylisation, not
the canonical brand mark. **Do not run it as-is** until it is updated
to read from `assets/branding/icons/orchestrate_app_icon_dark_1024.png`.
Running it today silently overwrites this directory with wrong-brand
output.

## Notes

- Google Play applies rounded corners and shadows dynamically; the
  source icon intentionally stays square.
- Store screenshots are not generated by this script because they
  must reflect real authenticated app states.
- App signing, App Store provisioning, and MSIX packaging are
  separate release-setup tasks.
